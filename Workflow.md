# Как работать над проектом

## Запуск проекта

Установите зависимости (`npm install`), затем запустите CLI:

```bash
npm run cli
npm run cli -- --help
npm run cli -- --version
npm run cli -- --import ./mocks/test-data.tsv
```

Сценарий `cli` собирает TypeScript и запускает `dist/main.cli.js`. Без аргументов
показывается справка. `npm start -- --version` также запускает CLI.
После сборки можно выполнять `node dist/main.cli.js --import ./mocks/test-data.tsv`.
Ошибки выводятся в stderr, код завершения — 1; успешное выполнение — 0.
За один запуск выполняется одна команда.

Команда `--import` читает TSV потоком и обрабатывает по одному предложению,
проверяет преобразование полей к нужным типам и выводит каждое предложение
в консоль в JSON, затем количество прочитанных предложений. При перенаправлении
вывода команда ожидает освобождения буфера stdout. Файлы больше 2 GB не загружаются
целиком в память. Запись в MongoDB пока не реализована. При ошибке обработка
прекращается; сообщение содержит файл, номер строки и число обработанных предложений.

Для генерации сначала запустите тестовый REST API в отдельном терминале:

```bash
npm run mock:server
```

Затем получите заготовки с ресурса `/offers`, создайте TSV и импортируйте его:

```bash
npm run cli -- --generate 100 ./mocks/generated.tsv http://localhost:3000/offers
npm run cli -- --import ./mocks/generated.tsv
```

`--generate <n> <filepath> <url>` принимает положительное целое безопасное число,
путь к TSV и полный HTTP(S) URL ресурса с массивом заготовок. Адрес сервера
передаётся аргументом, а не зашит в код. В `mocks/mock-server-data.json` подготовлено
шесть заготовок: названия, описания, города, превью, по шесть фотографий и авторы.
Ссылки на изображения используют демонстрационный домен example.com.
Команда проверяет ответ сервера и случайно выбирает заготовки, тип жилья,
дату за последние 30 дней, рейтинг, комнаты, гостей, стоимость, удобства и координаты
рядом с центром города. Избранное выключено, комментариев нет.
Запись выполняется потоком с учётом скорости диска; файл перезаписывается.
При ошибке записи может остаться неполный файл. Тайм-аут HTTP-запроса — 10 секунд.

Для проверки большого файла после сборки (понадобится несколько GB свободного места):

```bash
node --max-old-space-size=64 dist/main.cli.js --generate 4000000 ./mocks/large.tsv http://localhost:3000/offers
node --max-old-space-size=64 dist/main.cli.js --import ./mocks/large.tsv > import-result.log
```

Проверьте размер созданного файла: он должен превышать 2 GB. Полный JSON-вывод
будет значительно больше TSV; для проверки без сохранения вывода используйте
`> NUL` в cmd.exe или `> /dev/null` в Bash. После проверки удалите тестовые файлы.

Проверка выполнена на Node.js 24.13.0: сгенерировано и импортировано
3 637 414 предложений, размер TSV — 2 222 104 398 байт (больше 2 GiB).
Обе команды запущены с `--max-old-space-size=64` и завершились с кодом 0.
Генерация заняла около 132 секунд, импорт — 91 секунду. При импорте stdout
направлен в нулевое устройство; временный TSV после проверки удалён.

### Формат TSV

Файл в UTF-8, поля разделены табуляцией, одна строка — одно предложение.
Порядок 21 поля соответствует заголовку `mocks/test-data.tsv`:
`Title`, `Description`, `PublicationDate`, `City`, `PreviewImage`, `Images`,
`IsPremium`, `IsFavorite`, `Rating`, `Type`, `Rooms`, `Guests`, `Price`, `Goods`,
`AuthorName`, `AuthorEmail`, `AuthorAvatar`, `AuthorType`, `CommentsCount`,
`Latitude`, `Longitude`.

Заголовок необязателен. Списки изображений и удобств разделены `;`, флаги имеют
значения `true`/`false`, дробные числа используют точку. Пустые строки пропускаются,
поддерживаются LF, CRLF и UTF-8 BOM. Табуляции и переводы строк внутри полей
не допускаются. В тестовом файле `CommentsCount` равен 0: комментарии не импортируются.
Географические координаты города берутся из ТЗ, а последние два поля задают
координаты жилья. Данные автора выводятся отдельно от предложения; его `authorId`
будет назначаться при сохранении пользователя в БД. Пароль в этом формате отсутствует,
поэтому создание учётной записи по этому файлу не производится.

### Переменные окружения

Для текущего CLI переменные окружения не требуются. Путь к TSV задаётся аргументом
`--import`/`--generate`, URL сервера — аргументом `--generate`; адреса и доступы
к БД не используются. Для изменения порта тестового сервера:
`npm run mock:server -- --port 3001`.

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Проверить CLI тестами

```bash
npm test
```

Собирает проект и запускает тесты стандартным модулем `node:test`:
генерация и обратное чтение TSV, диапазоны значений, границы блоков UTF-8,
обработка ошибок и полный цикл CLI через локальный HTTP-сервер.
Тесты создают временные файлы и удаляют их после завершения.

#### Запустить тестовый JSON-сервер

```bash
npm run mock:server
```

Запускает json-server с `mocks/mock-server-data.json` на порту 3000.
Ресурс `http://localhost:3000/offers` возвращает заготовки для `--generate`.
Изменения файла отслеживаются автоматически.

#### Запустить CLI

```bash
npm run cli -- --import ./mocks/test-data.tsv
```

Собирает проект и выполняет указанную команду CLI. Без аргументов выводит справку.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Запустить проект

```bash
npm start
```

В процессе запуска проекта будет выполнен процесс «Сборки проекта» и запуска результирующего кода.

## Структура проекта

### Директория `src`

Исходный код проекта: компоненты, модули и так далее. Структура директории `src` может быть произвольной.

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.
